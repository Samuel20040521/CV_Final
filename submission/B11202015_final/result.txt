== Algorithm summary ==

Single-file implementation in computeDisp.py. Standard Middlebury 4-step
pipeline with the following design choices:

1. Cost computation:   9x7 Census transform + Hamming distance.
                       Popcount uses numpy.bitwise_count (numpy >= 2.0) when
                       available, otherwise falls back to a vectorised SWAR
                       (SIMD-Within-A-Register) implementation that runs
                       ~3.5x faster than the per-byte lookup table.
2. R-direction cost:   Built from cost_L via column reindex —
                       cost_R[d,y,x] = cost_L[d,y,x+d] with column clamp.
                       Skips an entire Hamming pass.
3. Cost aggregation:   Guided filter on the L cost only (radius=7, eps=1e-2,
                       BGR guide). The R cost feeds directly into the LR
                       consistency check un-aggregated — measurably better on
                       small-disparity images, only modestly worse on
                       Teddy/Cones, saves an entire filter pass.
4. Optimization:       Per-pixel winner-take-all (argmin over disparity).
5. Refinement:
   a. Left-right consistency check (threshold = 1).
   b. Scanline hole fill: min(nearest-valid-left, nearest-valid-right),
      max_disp padding at boundary.
   c. Parabolic sub-pixel disparity around the WTA argmin.
   d. Weighted median filter (radius=15). Sub-pixel float is cast directly
      to uint8 (max_disp ≤ 255), trading the previous [0, 255] stretch for
      a one-step cast — the implicit floor of small negative parabolic
      deltas acts as a helpful tie-breaker in the median window.

Allowed cv2.ximgproc primitives used: createGuidedFilter, weightedMedianFilter.
Does NOT use cv2.StereoBM, cv2.StereoSGBM, or any other built-in stereo solver.
No deep-learning components. No custom C extensions.
