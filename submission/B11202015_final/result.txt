== Algorithm summary ==

Single-file implementation in computeDisp.py. Middlebury 4-step pipeline,
parallelised across disparity slices:

1. Cost computation:   9x7 Census transform + Hamming distance, popcount
                       via numpy.bitwise_count when available, otherwise
                       a vectorised SWAR fallback.
2. R-direction cost:   Built from cost_L via column reindex —
                       cost_R[d,y,x] = cost_L[d,y,x+d] with column clamp.
3. Cost aggregation:   Weighted Guided Image Filter (Li 2015) implemented
                       directly with cv2.boxFilter primitives. The eps
                       parameter is per-pixel:

                           γ(x)   = (var_I(x) + eps0) / mean(var_I + eps0)
                           eps(x) = eps_base / γ(x)

                       γ is large at edges (so eps small → edge preserved)
                       and small in smooth regions (so eps large → denoised).
                       Hyperparameters depend ONLY on image content; no
                       branching on max_disp or image name.
                       Settings: radius=5, eps_base=5e-4, eps0=1e-6.
4. Optimization:       Per-pixel winner-take-all (argmin over disparity).
5. Refinement:
   a. Left-right consistency check (threshold = 1).
   b. Scanline hole fill: min(nearest-valid-left, nearest-valid-right),
      max_disp padding at boundary.
   c. Parabolic sub-pixel disparity around the WTA argmin.
   d. Weighted median filter (radius=15) on the sub-pixel disparity.

Per-disparity Hamming and per-disparity aggregation are dispatched to a
ThreadPoolExecutor (workers = min(cpu_count, 8)) — numpy and cv2 release
the GIL during their C-level work, so multi-core graders see near-linear
speedup on the parallelisable parts.

Allowed cv2.ximgproc primitives used: weightedMedianFilter.
(The guided filter is now implemented directly on cv2.boxFilter so it can
expose a per-pixel eps; the cv2.ximgproc.createGuidedFilter version is
retained as a reference in earlier git history.)

Does NOT use cv2.StereoBM, cv2.StereoSGBM, or any other built-in stereo
solver. No deep-learning components. No custom C extensions. No branching
on max_disp or image name (TA 2026-05-27 supplementary rule).
